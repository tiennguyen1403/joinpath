  - **Endpoint:**

    | Endpoint | Thành công | Lỗi |
    |---|---|---|
    | `GET /templates` | 200, sắp theo tên | |
    | `POST /templates` | 201, kèm DRAFT v1 rỗng | 400 |
    | `GET /templates/:id` | 200 | 404 |
    | `POST /templates/:id/versions` | 201, DRAFT n+1 | 409 |
    | `GET /template-versions/:id` | 200 | 404 |
    | `PUT /template-versions/:id` | 200, trả kèm `issues` | 400, 409 |
    | `POST /template-versions/:id/publish` | 200 | 400, 409 |
    | `POST /templates/:id/archive` | 200 | 409 |

  - **Pattern cho mọi lệnh ghi** (M1.4 nên làm theo):
    - `findFirst` theo id + `organizationId`; không có thì 404 (BR-P02).

    - Gọi `recordAudit` trong cùng `$transaction`.
    - Response dựng từ `select` cố định qua `toTemplate` và `toVersion`.
  - **PUT:**
    - Thứ tự kiểm: 404 → 400 (lỗi Zod) → 409.
    - Lưu đúng output của `templateDefinitionSchema.parse()`, rồi trả về `issues = validateTemplate(def)`.
    - Không ghi audit. Chỉ là một lệnh CAS, không cần transaction.
  - **Publish:**
    - Parse lại definition lấy từ DB.
    - Còn issue → 400 `VALIDATION_FAILED`. Message "Fix N problem(s) to publish" lấy theo tooltip trên canvas; `details` là `TemplateIssue[]`.
  - **Tạo version mới:**
    - Đọc version mới nhất. Nếu đó là DRAFT → 409 "Template already has a draft".
    - Nếu không, tạo DRAFT n+1 copy definition của bản đó, tức bản published mới nhất.
    - Khi hai request đến cùng lúc, partial unique chặn insert thứ hai (P2002 → 409).
  - **Archive:**
    - Archive lần hai → 409.
    - Template đã archive thì mọi lệnh tạo version, PUT, publish đều 409.
