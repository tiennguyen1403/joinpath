## Còn dở và nợ kỹ thuật

**Cho M3.4b:**
- **Chỗ đặt Activity trên trang chi tiết:**
  - Canvas vẽ Activity là card ở cột phải, dưới Invitation; tab "Activity" chỉ là link nhảy tới card đó.
  - Cần chốt bằng bảng trước/sau: card như canvas, hay tab thật (Graph thêm ở M4.3).
  - Người không phải HR hiện không có cột phải, vì Invitation chỉ HR thấy.
- **Câu chữ theo action do web viết:**
  - canvas ghi "submitted ID documents, revision 1", trong khi tên task là Upload ID documents;
  - approved và rejected gắn với task APPROVAL (Review ID documents);
  - actor của `onboarding.completed` là người làm task cuối cùng.
- **`picks`:** theo thứ tự template, không theo thứ tự HR chọn. Canvas gộp thành "picked Duc Tran for two IT tasks", nên web nhóm theo assignee; chọn để thành dòng riêng hay gộp vào dòng activated.
- **Thứ tự trong một lần activate:** `invitation.sent` ghi sau nên đứng trên `onboarding.activated` (mới nhất trước); canvas vẽ ngược lại. Web quyết, API không đổi thứ tự.
- **Tick không ghi audit:** task mở theo ngày, nhắc hạn, lời mời hết hạn không có trong timeline.
- **Phần web tự tính:** `GET /dashboard` trả mọi task mở, không giới hạn ngày. Web tự lo:
  - cửa sổ 7 ngày;
  - các con số và câu dưới lời chào;
  - "All waiting on one review": lần theo `dependsOn` tới task gốc. `waitsFor` trong `components/task-status.tsx` chỉ xét prerequisite trực tiếp.
- **Thiếu thiết kế:** canvas chưa có trạng thái rỗng và lỗi của dashboard.

**Khác:**
- **Draft trên template đã archive:** vẫn có `unassigned` (`planFor` không kiểm archive), nên web sẽ ghi "ready to activate" dù activate trả 409. Chưa có UI archive (M4.2), để tới đó.
- **Dữ liệu của sandbox mới:** mọi event của B, C nằm trong cùng một phút, lúc tạo sandbox (giới hạn đã ghi ở PLAN §4.6).

  - ý nút tải file ID mẫu;
  - `100vw` trên desktop;
  - các mục từ 027–029.
- **Lần push tới:** như handoff 030, cộng M3.4a. Không có migration mới.
